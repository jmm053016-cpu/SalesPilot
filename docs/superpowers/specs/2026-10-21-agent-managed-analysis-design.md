# Agent 驱动的数据导入与分析设计

日期：2026-10-21

## 目标与范围

将现有销售分析工作台升级为 Agent 编排的分析流程：用户提供文件或已配置的数据源后，以自然语言说明分析目标；Agent 自动识别字段、发起校验、保存有效数据集、构造分析请求并调用现有确定性分析服务；完成后，用户可基于持久化分析结果继续与 Agent 讨论。

正常路径不要求用户手工确认字段映射、点击保存或单独点击运行分析。数据源本身仍由用户上传或由管理员预先配置。无法可靠映射、数据校验失败或分析参数不明确时，流程必须暂停并给出可理解的原因，不能猜测后继续。

本次不改变既有销售指标口径，不让大模型计算或改写分析数值，不开放任意 SQL、Python、shell、文件路径访问，也不移除传统 UI 作为异常修复和人工确认入口。

## 当前实现

- `ui/data_entry.py` 负责读取 CSV、Excel 或受限 SQLite 查询，生成预览、字段映射和校验结果，并调用 `DatasetStore` 保存有效数据集。
- `AnalysisRequest` 和销售数据模型定义导入及分析的数据契约。
- `analytics.analysis_service.run_analysis` 执行确定性指标计算。
- `workflow.business_report.run_business_report` 编排分析、图表、报告解读与导出。
- `agent.analysis_tools.create_analysis_tools` 当前提供数据集检查、确定性分析和报告导出工具；追问 UI 通过已有 Agent runtime 运行。
- 会话和消息可持久化到 SQLite；数据集、分析结果及报告产物由各自的存储适配器管理，不能将它们误认为全部存放在会话 SQLite 中。

## 目标架构

### 1. 数据源接入

保留现有文件上传组件及支持的数据源边界。UI 上传后将数据源引用和导入元数据交给编排层，避免把大型表格内容反复塞入对话上下文。Agent 只能看到受控预览，例如列名、有限样例、推断类型、空值率和数据行数；敏感字段应在日志与不必要的模型上下文中排除或脱敏。

### 2. 字段映射

新增受控的导入分析工具，使用服务端数据源引用加载预览，并通过结构化输出要求模型给出 `ColumnMapping` 兼容的映射及必要的导入假设，例如数据粒度、币种和退款处理方式。模型输出必须经过模型契约与确定性规则校验：只允许已存在的源列和标准字段，目标字段不能重复，必需字段必须满足当前 schema 要求。

映射置信度不应仅依赖模型自报分数。程序应结合列名匹配、样例值及必需字段覆盖情况形成可解释的置信判断。高置信且无冲突时可自动继续；低置信、关键假设缺失或多列竞争同一字段时返回 `needs_user_input`，展示候选项供确认。

### 3. 校验和持久化

无论映射由 Agent 提出还是用户确认，最终都必须复用 `validate_and_normalize`。只有 `ValidationResult.valid` 且存在有效 `DatasetProfile` 时，才允许调用 `DatasetStore.save`。保存操作使用服务端生成的数据集 ID，并绑定当前 `session_id`。相同导入请求的重试应避免重复保存，可使用稳定的导入任务 ID 或幂等键识别重复操作。

校验失败时不保存数据集；Agent 仅总结错误类别、字段和行号范围，不应自行放宽规则。警告与错误需区分：警告可按已定义策略继续，影响指标可用性的假设必须写入数据画像或分析请求。

### 4. 分析请求和执行

Agent 从自然语言目标中抽取日期范围、对比类型、分组维度和异常阈值等参数，并生成 `AnalysisRequest`。参数必须通过 Pydantic 契约校验，并依据 `DatasetProfile` 检查字段、期间覆盖及指标可用性。日期范围无法确定或会显著改变结果的业务假设缺失时，向用户追问；其余参数可使用明确的系统默认值并在结果说明中披露。

通过校验后调用现有 `run_analysis` 或 `run_business_report`，数值仍由确定性代码生成并写入 `AnalysisStore`。Agent 不得直接构造指标值、排名或异常结果。Agent 工具沿用 `session_id` 与服务端资源 ID 的授权边界，并继续限制工具调用次数和超时。

### 5. 分析后讨论

分析完成后，将 `analysis_id`、`dataset_id` 和当前会话/对话绑定，并把精简的结构化分析摘要作为 Agent 可访问上下文。追问回答须基于已保存的 `AnalysisResult`、证据及数据画像；需要新口径或新期间时，Agent 应生成新的结构化请求并再次调用确定性分析工具，而不是在文本中估算新数字。

会话持久化保存用户与 Agent 消息及资源引用；分析数据继续由分析存储负责。应用重启后，根据持久化会话引用恢复上下文，若引用资源不存在或当前会话无权访问，应明确提示而非退化为无依据回答。

## Agent 工具边界

目标工具能力按职责划分，可在实现时合并为少量原子操作，但不得提供通用执行接口：

- `inspect_import_source(source_id)`：返回受限预览和数据画像。
- `propose_column_mapping(source_id, mapping, import_options)`：校验结构化映射并返回映射检查结果，不执行任意文件访问。
- `validate_and_save_dataset(source_id, mapping, import_options, idempotency_key)`：复用现有确定性映射、校验与存储服务，仅保存通过校验的数据集。
- `run_sales_analysis(dataset_id, request)`：验证资源授权和请求契约，调用确定性分析服务。
- `export_business_report(analysis_id, format)`：复用现有受控报告导出能力。

每个工具必须从运行时上下文获取会话身份，不接受模型自行指定 `session_id`、磁盘路径或任意 SQL。工具返回结构化状态，包括成功、需要用户输入、校验失败、未授权、资源不存在和可重试错误等类别。

## 交互状态与失败处理

流程状态至少包含：`awaiting_source`、`profiling`、`mapping`、`needs_user_input`、`validating`、`dataset_saved`、`analysis_planning`、`analyzing`、`completed` 和 `failed`。用户可在界面看到当前阶段、数据集/分析引用和可操作的错误信息；耗时步骤提供进度状态，重复提交不得造成重复导入或并发重复分析。

模型不可用时，现有手动映射和运行分析流程继续可用。模型超时或输出格式无效时不保存未经确认的映射，可有限重试后切回手动流程。上传内容、模型输出均视为不可信输入；不得因数据内容中的指令文本改变工具权限或系统策略。

## 持久化和安全

- 所有数据集、分析和产物读写均通过现有 session-aware store；跨会话 ID 必须拒绝访问。
- 会话存储只记录对话及资源引用，不把整个 DataFrame 或大型文件写入对话消息。
- 文件上传仍须执行扩展名、大小和解析错误控制；数据预览有行数及字段数上限。
- 日志记录阶段、耗时、资源 ID 和错误类别，不记录 API 密钥、整段原始数据或完整敏感样例。
- Agent 工具采用最小权限、固定工具集合、参数 schema、超时及调用预算。

## 验收标准

1. 对可明确映射且符合 schema 的 CSV/Excel，用户上传并提出分析目标后，可自动映射、确定性校验、保存数据集并运行分析，无需手工确认或点击“保存/运行分析”。
2. 对含歧义列、必需字段缺失或无效日期/金额的数据，不会错误保存或继续分析；系统返回具体问题，并提供人工确认/修复路径。
3. 自动流程、手动确认流程和重试流程共用同一映射、校验、持久化服务，保证规则一致并验证幂等行为。
4. Agent 生成的分析参数经过 `AnalysisRequest` 校验，最终指标与直接调用 `run_analysis` 的结果一致。
5. 分析后追问能够引用保存的分析证据；需要改变期间或维度时会发起新的分析调用；回答不捏造未返回的数值。
6. 跨会话访问、伪造资源 ID、任意路径/SQL/代码输入均被拒绝。
7. 模型缺失、超时、结构化输出错误、校验失败和存储失败都有明确状态，且模型缺失时手动流程仍然可用。
8. 对导入工具、映射置信与追问来源增加针对性测试；现有分析、持久化及报告测试继续通过。

## 分阶段交付建议

1. 抽取可由 UI 和 Agent 共用的导入服务，保持现有手动路径行为不变。
2. 增加结构化字段映射与导入工具，以及校验失败/需确认状态。
3. 增加自然语言分析请求规划和自动执行，把现有分析结果绑定到当前会话。
4. 打通分析后基于持久化证据的讨论与重启恢复，并验证完整端到端流程。

## 尚待实施计划中细化的事项

- 当前模型供应商对结构化输出的具体支持方式及测试替身。
- 自动映射置信规则的初始阈值与必需字段集，需以现有 schema 和 fixtures 编写测试后确定。
- 上传文件在 Streamlit 会话内的受控引用生命周期，以及重启恢复时是否要求用户重新上传未保存的数据源。
- 幂等键的生成范围、过期策略及重复请求响应。
