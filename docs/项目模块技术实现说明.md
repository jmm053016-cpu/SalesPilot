# SalesPilot 项目模块技术实现说明

本文档根据当前仓库实现整理，说明各模块的职责、采用的技术及主要实现方式。项目以确定性销售分析为核心，LLM 只负责受约束的文字解读和后续问答，不负责生成分析指标。

项目启动命令：uv run python -m streamlit run .\app.py

## 1. 项目技术栈

| 范围 | 技术 | 用途 |
| --- | --- | --- |
| 运行环境 | Python 3.12 | 应用及分析服务运行环境 |
| Web UI | Streamlit | 数据上传、分析配置、结果展示、对话及下载 |
| 数据处理 | pandas | 表格读取、清洗、筛选、分组和聚合 |
| 数据契约 | Pydantic v2 | 导入选项、数据档案、分析请求/结果、报告对象校验 |
| Agent | LangChain 1.x、LangGraph | 工具调用、Agent 运行时、中断/检查点状态和流式事件 |
| 模型适配 | langchain-openai / ChatOpenAI | 访问 OpenAI 兼容模型服务，包括 DeepSeek 兼容端点 |
| 图表 | Matplotlib | 根据已计算的分析结果绘制 PNG 图表 |
| 报告 | python-docx、ReportLab、pypdf | 生成 Word、PDF 并提取文本验证产物 |
| 本地持久化 | SQLite、JSON、CSV、文件系统 | 对话数据库、数据集及分析/报告元数据和文件 |
| 测试 | pytest | 单元、模块集成、工作流和端到端测试 |

依赖版本范围以 `requirements.txt` 和锁定文件为准。项目使用 `.env` 配置可选模型凭据；没有模型凭据时，确定性分析与报告导出仍可运行。

## 2. 总体架构与调用链

```text
Streamlit app.py
  ├─ UI：上传/字段映射/校验/分析配置
  ├─ data_sources：读取 CSV、Excel 或受限 SQLite 数据源
  ├─ storage：按 session_id 保存标准化数据、分析、产物和对话
  ├─ workflow.business_report
  │    ├─ analytics：指标、期间对比、排名、异常
  │    ├─ charts：分析图表
  │    ├─ reports.narrative：可选模型文字解读及确定性回退
  │    └─ reports：Word/PDF 导出
  └─ agent：基于当前会话资源调用受控工具，流式输出回答
```

典型数据流为：选择数据源并预览 → 自动/手动字段映射 → 校验、标准化并形成数据档案 → 将数据集绑定到当前会话 → 用户配置日期、分组和比较方式 → 执行确定性分析 → 生成图表、解读与报告 → 展示结果并提供会话范围内的下载入口。后续问答由 Agent 在当前会话绑定的数据集、分析及报告范围内调用工具。

## 3. 应用入口与工作流

### `app.py`

- **技术：** Streamlit、python-dotenv、各业务模块的组合入口。
- **实现：** 首先配置 Streamlit 页面，然后加载环境变量、配置日志、初始化并缓存存储对象。应用状态中维护分析会话、当前数据集/分析/报告引用和对话 UI 状态；会话初始化时从 `ConversationStore` 恢复活动对话，没有记录时创建新对话。
- **职责：** 编排页面阶段、调用 UI 渲染函数、将用户操作路由到导入、分析、报告或追问链路。业务计算被委托给 analytics/workflow，而不是直接写在页面代码中。
- **隔离：** session ID 是数据集、分析、产物和对话读写边界的一部分；恢复或下载资源时仍通过存储层校验归属。

### `workflow/business_report.py`

- **技术：** Python 工作流编排、结构化模型对象、日志与阶段计时。
- **实现：** `run_business_report` 按阶段执行：读取/复用分析结果 → 生成图表 → 生成解读 → 构建 `ReportModel` → 按请求格式导出 Word/PDF → 注册产物。每一阶段记录状态；图表或单种报告格式失败时记录警告/错误，并尽可能保留其它已成功结果。
- **职责：** 连接分析、图表、叙述和报告导出，不重新实现各自的业务算法。

## 4. 用户界面模块 `ui/`

### `ui/data_entry.py` 与 `ui/workbench.py`

- **技术：** Streamlit 控件、pandas DataFrame 预览、数据源加载和 DatasetStore。
- **实现：** 数据源选择封装为 `SourceSelection`；预览阶段读取文件、推断默认列映射、执行标准化和校验，并返回 `SourcePreview`。映射会检查源列是否存在、目标字段是否受支持以及映射是否重复。确认有效后才持久化为会话数据集。
- **职责：** 展示 CSV/Excel/SQLite 数据入口、字段与粒度/币种等导入选项、校验信息和分析配置；工作台将 UI 操作转换为领域请求。

### `ui/session.py`

- **技术：** 不可变 dataclass 与 Streamlit 会话状态。
- **实现：** `AnalysisSession` 保存 session、conversation、dataset、analysis、report 和 Agent thread 的引用。辅助函数负责新建会话、从持久化会话恢复状态、生成资源绑定以及重置 thread。
- **职责：** 管理页面会话中的资源引用，不负责存储数据本体。

### `ui/conversations.py`

- **技术：** ConversationStore 与 Streamlit 侧栏/消息组件。
- **实现：** 根据首条问题确定性截断生成标题；支持新建、切换及渲染历史对话。切换时将持久化会话恢复为 `AnalysisSession` 并清理页面级旧结果。是否允许继续追问还要检查会话状态和数据集是否仍存在。

### `ui/followup.py`

- **技术：** LangChain/LangGraph 事件流、UIEvent、Streamlit 聊天 UI。
- **实现：** 收集用户追问并调用 Agent 流式运行；将模型文本增量、工具开始/结束/失败事件呈现给用户；保存消息并清理/重置 thread 状态。工具事件通过 call ID 关联，避免多个工具调用的状态混淆。

### `ui/analysis_view.py`、`ui/theme.py`

- **技术：** Streamlit 展示组件、CSS 主题、HTML 阶段进度条。
- **实现：** 结果页展示结构化指标、对比、排名、异常、解读和图表，并依据报告产物引用提供下载。指标不可用时呈现原因。主题模块集中定义 CSS、状态色和阶段状态展示，避免各页面重复维护样式。

## 5. 数据接入与标准化 `data_sources/`

### 文件读取：`csv_source.py`、`excel_source.py`、`database_source.py`

- **技术：** pandas `read_csv` / `read_excel` / `read_sql_query`、Python sqlite3、openpyxl。
- **实现：** CSV 使用 UTF-8-SIG 读取；Excel 通过指定工作表读取；SQLite 查询采用代码中登记的查询名称与 SQL 模板（当前仅有 `orders` 查询），而不是接收任意用户 SQL。文件类数据源经过文件大小检查，所有数据源检查最大行数。
- **限制：** schema 定义单文件最大 20 MB、最多 100,000 行。

### 字段映射：`mapper.py`

- **技术：** pandas 列名及别名映射。
- **实现：** 先把列名去空格并转小写，与标准字段别名表匹配，构造源列到统一字段的 `ColumnMapping`。UI 允许用户查看和调整映射。

### 校验：`validator.py`、`schema.py`

- **技术：** pandas 类型归一化、Decimal 精度检查、Pydantic 校验模型。
- **实现：** 必需字段为订单日期和销售金额；将日期与数值转换为规范类型，检查非法值、负数及金额最多两位小数；处理退款、成本、数量、订单 ID、币种等可选字段。币种冲突会报错；未提供退款、成本、订单粒度等条件时，相应指标会记录为不可用及原因，而不是补造数据。
- **输出：** 规范化 DataFrame 与 `ValidationResult`，其中包含错误、警告和 `DatasetProfile`（字段、粒度、日期范围、币种以及可用/不可用指标）。

## 6. 领域模型 `models/`

### `models/sales.py`

定义导入选项、日期范围、字段映射、数据档案、校验问题和指标假设等销售数据契约。基类设置 `extra='forbid'` 并去除字符串首尾空格，枚举/数值边界通过 Pydantic validator 检查。

### `models/analysis.py`

定义分析请求、指标值、证据、期间比较、排名和异常以及最终 `AnalysisResult`。不可用指标要求附带原因；Decimal 指标拒绝非有限值；结果与请求的数据集 ID 必须一致。结构化证据提供稳定 ID，供报告叙述和图表关联。

### `models/report.py`

定义解读、观察、建议、图表、产物引用及 `ReportModel`。报告模型组合分析结果与可选叙述、图表、元数据和导出产物；schema version 不匹配时拒绝验证。

### `models/conversation.py`

使用 frozen dataclass 定义对话和消息，限制状态/角色取值，并验证必需标识、标题、内容及消息序号。消息 metadata 和报告 ID 在对象边界复制，减少外部可变容器带来的意外修改。

## 7. 确定性分析 `analytics/`

### `analysis_service.py`

提供分析服务入口 `run_analysis`。执行前验证数据集 ID、DataFrame 类型和必需列；之后统一调用指标、对比、排名与异常模块，并将结果转换为带 ID 的结构化证据。底层异常转换为带稳定错误代码的 `AnalysisServiceError`。

### `metrics.py`

使用 pandas 按日期区间筛选数据，以 Decimal 累加并按两位小数舍入，计算销售、净销售、毛利、毛利率、订单数、客单价和数量等可支持指标。实际计算受数据档案中的粒度、字段和已确认假设约束；不足时返回带原因的不可用值。

### `comparisons.py`

根据请求指定的比较类型构造对照期间，对期间内指标进行同口径计算并生成当前值、对照值和变化结果；覆盖完整性不足时保留完整性/原因说明，避免把不完整期间伪装成可靠增长率。

### `rankings.py`

按请求维度对日期范围内数据分组聚合，生成 Top N 排名；维度缺失或指标不可算时由上层跳过或返回不可用状态。

### `anomaly.py`

实现两类规则：对每日销售额使用历史窗口均值、标准差和 z-score 标识异常；对品类/区域使用相邻等长期间的相对下降幅度与绝对下降额双阈值识别下滑。历史样本不足时不输出统计异常；结果携带算法、阈值、严重程度和证据 ID。

## 8. 图表生成 `charts/`

- **技术：** Matplotlib 非交互式绘图，统一图表样式和文件保存逻辑。
- **实现：** `sales_charts.py` 从 `AnalysisResult` 生成排名、期间对比、异常、毛利或趋势等图表。缺少对应数据时跳过该图；每张图封装为 `ChartArtifact`，包含路径、类型、标题和来源证据 ID。
- **边界：** 图表只可视化分析结果，不重新计算业务指标。绘图风格与输出辅助逻辑放在 `chart_style.py`。

## 9. 报告生成 `reports/`

### `narrative.py`

- **技术：** 可选结构化 LLM 输出、Pydantic 校验、Decimal 数值核验。
- **实现：** 仅向模型提供计算好的指标、证据和期间；提示模型只引用输入证据 ID，不做新数值计算或添加未提供的日期。返回后检查观察/建议是否引用有效证据、文本中的数值是否能在证据中找到。模型缺失、响应无效或校验失败时生成明确标记为 `fallback` 的确定性事实摘要。

### `report_model.py`

将分析、叙述、图表和报告元数据组装成统一 `ReportModel`，作为 Word/PDF 导出共用的数据输入契约。

### `word_report.py`、`pdf_report.py`

- **技术：** python-docx 生成 DOCX；ReportLab 生成 PDF；统一返回 `ArtifactRef`。
- **实现：** 从同一报告模型读取核心指标、期间变化、排名、异常和解读，按章节与表格排版。缺失的分析或叙述显示为不可用提示，不影响确定性分析内容的保留。

### `render_verify.py`

- **技术：** python-docx 和 pypdf 文本提取。
- **实现：** 校验产物存在且非空、文件扩展名与 MIME 类型一致、文档能被解析，并检查核心指标、销售额、建议等必需内容。该模块用于导出产物的结构性验证，不负责创建报告。

## 10. Agent 运行时 `agent/`

### `agent_setup.py`🔴

- **技术：** LangChain Agent、LangGraph 检查点接口、ChatOpenAI。
- **实现：** 根据环境变量创建 OpenAI 兼容追问模型；优先使用 OpenAI 配置，否则复用 DeepSeek 配置。报告解读模型单独构造为 `NarrativeResult` 结构化输出。运行时通过 LangChain Agent 将模型与已提供的工具、系统提示、middleware 和 checkpointer 组合；框架条件不满足时兼容运行时保留回退路径。

### `analysis_tools.py`

暴露三个受限工具：

1. `inspect_dataset`：读取当前会话拥有的数据档案，返回字段、粒度、可用指标和约束。
2. `run_sales_analysis`：解析结构化请求，验证会话和数据集归属，再调用确定性分析并保存结果。
3. `export_business_report`：基于已保存分析生成指定格式报告并注册产物。

工具通过运行时上下文取得 session/thread 资源，不接受任意 SQL、Python、文件路径或用户代码执行请求。

### `state.py`、`context.py`

`AgentState` 表示 Agent 消息/运行状态；`InMemorySaver` 以 `(session_id, thread_id)` 为键保存检查点状态，并在可用时适配 LangGraph saver。运行时上下文将工具操作绑定到当前会话资源，避免工具只凭模型提供的 ID 任意访问数据。

### `prompts.py`、`middleware.py`

系统提示限定助手身份和可执行任务；middleware 为模型和工具调用设置超时，并通过工具调用预算限制循环调用。超时和预算超限转为可识别的运行时错误。

### `events.py`、`callbacks.py`

`events.py` 将 LangGraph/LangChain 的多种流事件适配成稳定 `UIEvent`（文本增量、工具开始/完成/失败），UI 只需消费统一事件格式。`callbacks.py` 提供 Streamlit callback handler，将工具状态和模型 token 写入页面占位容器及会话状态。

## 11. 持久化 `storage/`

### `datasets.py`、`profiles.py`

数据集以 CSV 保存、元信息以 JSON 保存到 `.runtime/<session_id>/<dataset_id>/`。保存时校验档案会话归属；加载时校验标识格式、规范化路径、元数据内的 session/dataset ID 和文件完整性，阻止跨会话读取及路径越界。

### `analyses.py`、`artifacts.py`

分析对象和产物引用分别序列化为 JSON，按会话目录保存；读写前校验标识，只能通过请求会话 ID 下的对象路径查找。报告、图表等实际文件按工作流指定目录保存，元数据中登记 storage key。

### `conversations.py`

使用标准库 sqlite3 初始化对话和消息表及查询索引。对话记录保存资源绑定、状态和 Agent thread ID；消息按每个对话的递增序号保存，并将附加信息序列化为 JSON。查询、更新和归档接口均带 session ID，并校验活动状态及归属。

### `.runtime/` 布局

运行时数据默认置于仓库根目录 `.runtime/`，其中包括会话数据集、分析、产物、对话数据库、生成图表/报告和日志。该目录属于本地运行数据，不应提交到版本控制。

## 12. 通用工具 `utils/`

### `logging_config.py`

配置命名空间日志、控制台输出和按天轮转文件日志；日志级别由环境变量覆盖。`RedactingFormatter` 与异常摘要函数对常见 API key/Bearer 凭据模式脱敏并限制长度；无法创建日志文件时降级为控制台日志，不阻断应用启动。

### `helpers.py`

提供金额/货币显示等通用辅助函数。数据分析中的正式金额计算仍由 analytics 模块基于 Decimal 执行；展示/辅助转换逻辑不应作为正式分析口径。

## 13. 测试与发布校验

- **测试目录 `tests/`：** 按模块测试数据源、模型、分析算法、Agent 状态与工具、会话隔离/生命周期、UI 组件和报告工作流；`tests/fixtures/` 提供本地 CSV 样本。测试以可注入模型或 mock 为主，不要求调用在线模型服务。
- **发布脚本 `scripts/verify_release.ps1`：** 编译检查业务代码和测试、可选执行 pytest，并扫描 Agent/分析相关源码是否出现 `exec` 或 `eval` 调用。
- **运行：** `python -m pytest -q`；发布脚本默认还会运行编译与静态检查，可通过 `-SkipTests` 跳过 pytest。

## 14. 关键设计约束

1. **数值可信：** 指标、比较、排名和异常均由确定性 Python 逻辑计算；LLM 不能作为数值来源。
2. **证据可追溯：** 分析结果携带证据 ID；叙述和图表引用这些 ID，叙述还需通过引用及数值校验。
3. **缺失即说明：** 计算条件不足时返回不可用状态及原因，不用模型或默认值推测缺失业务数据。
4. **会话隔离：** 所有资源访问按 session ID 约束，存储层再次验证所有权，不仅依赖 UI 隐藏资源。
5. **工具收敛：** Agent 只能调用已登记的业务工具，不提供通用 SQL、代码执行或路径访问能力。
6. **模型可选：** 模型服务不可用时，核心导入、确定性分析及报告生成链路仍可工作；模型文字解读可退化为事实摘要，追问功能需要模型凭据。
